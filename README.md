## 🧭 **راهنمای گام‌به‌گام استقرار**

### ۱. مخزن را فورک یا کلون کنید:
```bash
git clone https://github.com/AyhanMansur/Xui-Panel.git
```

### ۲. به [Railway.app](https://railway.app/) بروید و یک پروژه‌ی جدید بسازید.
- گزینه‌ی **Deploy from GitHub repo** را انتخاب کنید.
- ریپازیتوری `Xui-Panel` را انتخاب کنید.
- (اختیاری) متغیرهای محیطی را تنظیم کنید (در ادامه توضیح داده می‌شود).

### ۳. Railway به‌طور خودکار `Dockerfile` را شناسایی کرده و بیلد می‌کند.
- بیلد حدود ۲ دقیقه طول می‌کشد.

### ۴. بعد از اتمام دیپلوی، آدرس عمومی (مثلاً `https://your-app.railway.app`) را دریافت کنید.

### ۵. پنل را با مسیر `/managepanel/` باز کنید:
```
https://your-app.railway.app/managepanel/
```

### ۶. با مشخصات پیش‌فرض وارد شوید:
- **نام کاربری**: `admin`
- **رمز عبور**: `admin`

> ⚠️ **فوراً پس از ورود، رمز عبور را تغییر دهید!** (از طریق تنظیمات پروفایل)

## 🧩 **تنظیمات پیشرفته: VLESS + TCP + Reality با TCP Proxy**

یکی از قدرتمندترین و امن‌ترین روش‌ها برای استفاده از این پنل روی Railway، پروتکل **VLESS** با ترانسپورت **TCP** و لایه‌ی امنیتی **Reality** است.  
چون Railway به‌طور پیش‌فرض فقط پورت `443` و `80` را برای HTTP Load Balancer باز می‌گذارد، برای اتصال کلاینت‌ها باید از قابلیت **TCP Proxy** خود Railway استفاده کنیم.

### 🔧 قدم اول: ساخت اینباند VLESS+TCP+Reality در پنل

- وارد پنل شوید و به بخش **Inbound** بروید.
- روی **Add Inbound** کلیک کنید و تنظیمات زیر را وارد کنید:
  - **Protocol**: `VLESS`
  - **Transport**: `TCP`
  - **Reality**: فعال (روی دکمه‌ی **Reality Settings** کلیک کنید)
  - **Port (داخلی)**: مثلاً `8443` (هر پورت دلخواه بالای ۱۰۰۰)
  - **UUID**: خودکار تولید می‌شود (می‌توانید تغییر دهید)
  - **Flow**: `xtls-rprx-vision` (توصیه می‌شود)
  - **Reality تنظیمات**:
    - **PublicKey**: از کلید عمومی تولید شده در پنل کپی کنید
    - **PrivateKey**: به‌طور خودکار ساخته می‌شود (نگهداری کنید)
    - **ShortId**: یک رشته‌ی ۸ کاراکتری (مثلاً `12345678`)
    - **ServerNames (SNI)**: یک دامنه‌ی معتبر مثل `cloudflare.com` یا `yahoo.com` (هر دامنه‌ای که TLS داشته باشد)
    - **Fingerprint**: `chrome` یا `firefox` یا `random`
- روی **Save** کلیک کنید تا اینباند ساخته شود. پورت داخلی (`8443`) را یادداشت کنید.

### 🔗 قدم دوم: ایجاد TCP Proxy در Railway

- وارد پیشخوان پروژه‌ی خود در Railway شوید.
- به برگه‌ی **Settings** بروید و بخش **Networking** را پیدا کنید.
- روی **Add TCP Proxy** کلیک کنید.
- در فیلد **Internal Port** عدد پورت داخلی اینباند (مثلاً `8443`) را وارد کنید.
- Railway به‌طور خودکار یک **Public Port** (مثلاً `28765`) به شما اختصاص می‌دهد. (در بعضی حساب‌ها می‌توانید پورت دلخواه را هم انتخاب کنید).
- روی **Save** بزنید.

### 📡 قدم سوم: دریافت آدرس نهایی برای کلاینت

بعد از ذخیره‌سازی، Railway اطلاعات زیر را نمایش می‌دهد:

- **Host (آدرس)**: `your-app.up.railway.app` (همان دامنه‌ی عمومی اپلیکیشن شما)
- **Port (پورت عمومی)**: مثلاً `28765`

> ✨ این همان `host:port` است که باید در کلاینت خود وارد کنید.

### 📱 نمونه‌ی کانفیگ نهایی (VLESS+TCP+Reality)

فرض کنید اطلاعات شما به این صورت است:

- آدرس: `xui-panel-production.up.railway.app`
- پورت عمومی: `28765`
- UUID: `your-uuid-here`
- PublicKey: `your-public-key-here`
- ShortId: `12345678`
- SNI: `cloudflare.com`
- Fingerprint: `chrome`
- Flow: `xtls-rprx-vision`

**کانفیگ JSON (برای Xray):**
```json
{
  "inbounds": [],
  "outbounds": [
    {
      "protocol": "vless",
      "settings": {
        "vnext": [
          {
            "address": "xui-panel-production.up.railway.app",
            "port": 28765,
            "users": [
              {
                "id": "your-uuid-here",
                "flow": "xtls-rprx-vision",
                "encryption": "none"
              }
            ]
          }
        ]
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "serverName": "cloudflare.com",
          "fingerprint": "chrome",
          "publicKey": "your-public-key-here",
          "shortId": "12345678"
        }
      }
    }
  ]
}
```

**برای کلاینت‌های موبایل (مثل V2RayNG / NekoBox):**
- آدرس: `xui-panel-production.up.railway.app`
- پورت: `28765`
- UUID: `your-uuid-here`
- Flow: `xtls-rprx-vision`
- Encryption: `none`
- Transport: `tcp`
- Reality: فعال با SNI, PublicKey, ShortId, Fingerprint

## ⚠️ **نکات طلایی و عیب‌یابی**

| مشکل | راه‌حل |
|------|--------|
| پورت عمومی وصل نمی‌شود | مطمئن شوید که **TCP Proxy** درست ذخیره شده و پورت داخلی دقیقاً با پورت اینباند یکی است. |
| کلاینت خطای `handshake failed` می‌دهد | SNI و Fingerprint را با کلاینت خود چک کنید. برای Reality حتماً SNI باید یک دامنه‌ی معتبر با TLS باشد. |
| پنل باز نمی‌شود | مسیر `/managepanel/` را فراموش نکنید و از `https` استفاده کنید. پورت `2053` باید در Railway به‌طور خودکار در دسترس باشد. |
| ترافیک بالا و محدودیت Railway | Railway ماهانه ۵۰۰ ساعت رایگان دارد (برای هر حساب). در صورت نیاز می‌توانید چند اپلیکیشن بسازید یا از چند حساب استفاده کنید. |
| تداخل پورت‌ها | پورت `2053` برای پنل و پورت اینباند (مثلاً `8443`) کاملاً مجزا هستند. نیازی به تغییر پورت پیش‌فرض نیست. |
| خطای `tls: handshake failure` در کلاینت | از صحت PublicKey و ShortId مطمئن شوید. همچنین زمان سرور خود را همگام‌سازی کنید (NTP). |

## 🔐 **امنیت و بهینه‌سازی**

- پس از ورود، رمز عبور پیش‌فرض را تغییر دهید.
- از **Strong UUID** و **ShortId** استفاده کنید (تولید خودکار پنل کافی است).
- برای Reality از **SNI دامنه‌های پرترافیک** مثل `cloudflare.com` استفاده کنید تا تشخیص داده نشود.
- توصیه می‌شود **Fail2ban** یا محدودیت IP را در پنل فعال کنید.
- به‌روزرسانی‌های ۳X-UI را از طریق پنل انجام دهید (`Settings > Update`).
- برای افزایش پایداری، از **Health Check** در Railway استفاده کنید (مسیر `/managepanel/` را تنظیم کنید).

---

## 💡 **نکات تکمیلی برای کاربران حرفه‌ای**

- می‌توانید از **متغیرهای محیطی** در Railway برای تغییر پورت پنل یا مسیر استفاده کنید (مثلاً `XUI_PORT=2053` و `XUI_PATH=/myadmin`).
- برای اتصال از طریق **CDN** (مانند Cloudflare) باید پروتکل را به **WebSocket** یا **gRPC** تغییر دهید و از **TCP Proxy** صرف‌نظر کنید.
- برای افزایش سرعت، دیتاسنتر نزدیک به خود را در Railway انتخاب کنید (در تنظیمات منطقه‌ی پروژه).
- می‌توانید از **Railway CLI** برای مدیریت و لاگ‌گیری پیشرفته‌تر استفاده کنید.
